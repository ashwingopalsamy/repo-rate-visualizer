# Policy Rate Atlas v2: Design

Date: 2026-10-07 · Revision 2 (after adversarial review) · Status: approved 7 Oct 2026; visual direction revised to the Agam language (§6.5–6.6)
Visual and motion reference: specimen v4, https://claude.ai/artifact/GtAzmwb7Ly811KjE19mM39 (Agam shell, Claret palette, official series for 7 central banks)

## 1. Intent

The one credible, beautifully made place to see every major central bank's policy rate: what it is, how it got there, when it next changes, and what that means for a borrower. Search visitors usually land on one country page during the hour after a decision. That page must already be right. Humans, search engines and agents (REST, MCP, WebMCP) read the same verified data. Hosting and pipeline cost stay at $0.

**What the owner asked for:**
- One architecture for every country.
- India data kept as is, plus today's hike.
- The US experience fixed.
- At least the top 10 economies that matter for traffic.
- An always-on, compute-efficient refresh scheduled per country.
- A delightful, soulful, non-generic UI with a country switcher.
- An API and WebMCP.
- Zero cost.

**Assumed (correct me):**
- The name stays "Policy Rate Atlas".
- The domain is `rates.ashwingopalsamy.in`.
- The UI is in English only.
- History runs from 2000 where official sources allow.
- The RBI Hugging Face dataset keeps its current shape.

### Value proposition: what a visitor gets that nobody else gives them
Other sites list the rate or plot a line. The Atlas answers the questions people actually arrive with, each in one sentence computed from verified official records, with the chart underneath as evidence:

| Visitor question | Answer on the page | Computed from |
|---|---|---|
| What just happened? | The lede: "raised by 25 bps to 5.50%, its first hike since February 2023, after ten months unchanged" | Decision records |
| What does it mean for my loan? | The change in local currency per month, or the tenure change, with an honest note on how this country's loans follow the policy rate | `transmission` data + standard amortisation |
| Is this high or low? | "Lower than on 72% of days since 2004", with time spent at each level | Effective-dated series |
| Where are we in the cycle? | This cycle against every earlier one in the same direction, plus their median size and length | Cycle detection (§3) |
| How does it compare with the Fed? | The gap in bps, its share-of-days rank, and the year-ago gap, with plain words on why the gap matters for the currency | Two series |
| What is the rest of the world doing? | "4 of 7 central banks raised rates in the last 90 days, the widest tightening turn since October 2023", plus the latest decisions worldwide and a sortable table | All countries' decisions |
| When is the next one? | Countdown in the bank's time and the viewer's | Calendars (§4) |

**The moat:**
- Decision-level, official-source data that is verified within 45 minutes of an announcement.
- Findings that are deterministic and auditable, never generated by an LLM.
- Honest coverage: eras, labelled gaps, no midpoints.
- The same answers served to agents through MCP and WebMCP, so assistants cite the Atlas.

**Rule:** every panel opens with a finding and a "kick" naming the question. A panel whose finding cannot be computed honestly is cut, not decorated.

### Success criteria
- **One shell for every country.** Country pages share one shell and one component set. There are no country branches in UI code; all differences come from data.
- **Fast after an announcement.** A scheduled decision is published within 45 minutes of the announcement, for every country with a parsed press release. The target for each country is in §2.
- **Off-cycle moves within 48 hours.**
- **No false data, ever.** The site never shows a false "unchanged" or a stale "today" value. On decision day it shows the decision-day state (§5) until the decision is verified.
- **Idle days cost almost nothing.** A day with no due decision runs one sweep job and nothing else.
- **Every value is traceable.** It leads to an official source, or to a source explicitly labelled secondary.
- **Performance and accessibility.**
  - Lighthouse performance and accessibility ≥ 95 on a mid-range phone.
  - Main JS ≤ 90 KB gzip.
  - WCAG 2.2 AA.

### Non-goals (v2)
- Real rates and inflation, forecasts, market-implied paths.
- Corridor rates as separate series.
- UI languages other than English, accounts, ad tech.
- v1's notebook, release-diff UI, `/design` page and layers menu.

## 3. Data model (schema v3)

`schema/` holds the TypeScript types plus a runtime validator. The pipeline, the build, the Worker and the UI all import them.

```ts
type Bps = number;                                  // integer basis points
type Level =
  | { kind: 'point'; bps: Bps }
  | { kind: 'range'; lowBps: Bps; highBps: Bps }
  | { kind: 'none'; label: string };                // no rate target in this era

interface CountryRelease {
  schemaVersion: 3;
  country: { code; name; currency; locale; timeZone };
  authority: { name; short; body; bodyShort; url };
  instrument: { name; short; explainer: string };   // three-sentence "what is it"
  eras: { id; from; to: string | null; instrument: string; kind: Level['kind']; basis: 'policy' | 'observation'; note: string; sourceId }[];
  calendar: Meeting[];
  decisions: Decision[];                            // meeting-level, announcement-dated
  series: { date: string; level: Level; evidence: 'official' | 'secondary'; sourceId: string }[];  // effective-dated change points; findings use only points in 'policy' eras
  transmission: Transmission[];
  context: { date; label; description; sourceId }[];  // sourced events (India's v2 events land here)
  sources: Source[];
  coverage: { seriesFrom; ledgerFrom: string | null; grain: string };
  release: { hash: string; generator: string; upstream?: { kind; id; sha256 } };  // excluded from hashing
}

interface Meeting {
  id: string;                       // `${cc}-${yyyy-mm-dd}`
  meetingStart: string | null;      // multi-day meetings → "in session" state
  announceAt: string;               // zoned ISO, e.g. 2026-10-07T10:00:00+05:30
  effectiveLagDays: number;         // series lag after announcement (US 1, EA ~6, …)
  status: 'scheduled' | 'held' | 'cancelled' | 'moved';
  movedTo?: string; sourceId: string;
}

interface Decision {
  id: string; meetingId: string | null;             // null for off-cycle
  announcedAt: string;                               // zoned ISO
  effectiveDate: string | null;
  level: Level;
  direction: 'hike' | 'cut' | 'hold' | 'unchanged' | 'none';  // 'hold' needs a statement; 'unchanged' = scheduled meeting, series flat, no statement
  changeBps: number | null;                          // null across an era boundary
  eraChange: boolean;                                // e.g. Fed 2008-12-16 (a cut), BoJ 2024-03-19 (a hike)
  offCycle: boolean;
  evidence: 'statement' | 'series' | 'secondary';
  vote: { for: number; against: number; dissents: string[] } | null;  // null renders "Vote not captured"
  stance: string | null;
  statementUrl: string | null;
  excerpt: string | null;                            // ≤ 1 sentence quoted from the statement
  sourceIds: string[];
}

interface Transmission {
  product: string;            // "Floating-rate home loan", "Credit card (prime-linked)"
  benchmark: string;          // "External benchmark (repo-linked)", "Prime = upper bound + 300 bps", "5Y LPR"
  spreadBps?: number; reset: string; adjusts: 'payment' | 'tenure' | 'both';
  passThrough: 'direct' | 'lagged' | 'weak' | 'none'; note: string; sourceId: string;
}
```

### Invariants
A release that violates any of these is never written.

1. **Levels.**
   - Rates are integers in bps.
   - A range always has `low < high`.
   - Midpoints are never stored or shown.
   - `none` levels are never drawn as a value; they appear as era gaps with a label.
2. **Ordering and change.** `series` dates ascend strictly. Within one era, `changeBps` equals the new level minus the old one. Across an era boundary, `changeBps` is `null`, `eraChange` is `true`, and `direction` still records the economic move when there is one.
3. **Decisions and calendar.** Every decision with `meetingId` matches a `held` meeting. Every `held` meeting at or after `coverage.ledgerFrom` has exactly one decision. A `cancelled` or `moved` meeting never has one.
4. **Holds.** `direction: 'hold'` requires `evidence: 'statement'`. `direction: 'unchanged'` with `evidence: 'series'` is allowed only when both hold:
   - no statement was parsed;
   - the series has an observation dated on or after `announce date + effectiveLagDays` that shows no move.

   Otherwise the decision stays pending (§4).
5. **Decisions agree with the series.** Once the series has an observation dated on or after a decision's effective date, its level must equal the decision's level. A mismatch fails the run and opens an issue.
6. **Sources.**
   - Every `sourceId` resolves.
   - URLs are on the country's allowlisted official domains unless typed `secondary`.
   - Source URLs are human-facing pages, never API URLs that carry a key.
7. **Unknown values stay null.**
8. **Content addressing.** `release.hash` = SHA-256 of canonical JSON with the `release` block excluded. Retrieval time is not hashed, so a no-change run produces identical bytes and no commit.
9. **History is append-only.** A new release must contain every earlier decision and series point unchanged. Revisions need a `corrections[]` entry (reason and source) and land through a reviewed PR, never through the bot.
10. **Trust boundary.** Text from sources enters only via `excerpt`, after escaping. Ledes, summaries and agent text are generated from structured fields.

### India
The RBI fetcher, v2 snapshots, `src/data/snapshot.json` and the HF build stay. A projector maps v2 to v3:
- **Statements:** records backed by a resolution become `statement` decisions.
- **Secondary observations:** Reuters and Shriram observations become `secondary` series points, never decisions.
- **Pre-2004 records:** these sit in their own era. Phase 1 verifies their meaning before deciding how to present them; they get no decision permalinks either way.
- **Stance and events:** `stance` carries over; v2 `events` become `context`.
- **Regimes:** v2 `regimes` stay in the HF dataset; v3 computes cycles.
- **Unknown sources:** an unknown v2 source type fails the projection.

**Write order:**
1. Fetch.
2. Build the v2 candidate.
3. Project to v3.
4. Validate v3.
5. Only then write v2, v3 and the HF artifacts, all in the same commit.

**Known gap:** the v2 ledger is missing MPC meetings, including the 6 Feb 2026 hold and the 2020–22 holds. India's `ledgerFrom` is therefore set late until the additive backfill (decision D2) runs.

### Cycles (computed, documented on /methodology)
- A cycle is a maximal run of same-direction moves. Holds do not break it; an opposite move does.
- A bank's state at time t (tightening, easing or on hold) is the direction of its latest move within the previous 182 days; otherwise it is on hold. Eras with a `none` level show as hatched gaps.

## 4. Pipeline and scheduling

### Dispatcher: Cloudflare Cron Trigger, free
A Worker `scheduled` handler runs every 10 minutes. It reads `/data/schedule.json` from the asset store; this file is generated at build with the next and last 48 h of meetings and whether each is resolved.

**Dispatch rules:**
- **Scheduled meetings:** dispatch `refresh.yml` with `{countries, reason, meetingIds}` through the GitHub API when a meeting is unresolved and now sits on the retry ladder: `announceAt` + 10, 25, 45, 90, 180 and 360 minutes. After +360 the dispatcher opens an issue.
- **Daily sweep:** once a day at 06:17 UTC it dispatches a sweep of all countries. The sweep catches off-cycle moves, CN, and series reconciliation.

**Why this design:**
- GitHub Actions runs only when there is work.
- Timing is precise; GitHub's own cron is delayed and sometimes dropped.
- It avoids the 60-day auto-disable that hits scheduled workflows.

**Credentials:** a fine-grained GitHub token, scoped to this repo with `actions:write` only, stored as a Worker secret (decision D1).

**Backstop:** `refresh.yml` keeps a weekly schedule (`17 3 * * 0`) in case the dispatcher fails.

### Workflow `refresh.yml`
- **Job `fetch`.** Runs a matrix over the dispatched countries with `fail-fast: false` and `setup-node` from `.node-version`. Each leg:
  - runs the decision adapter, then the series adapter;
  - checks the invariants (§3), building a candidate release and resolving each meeting as `verified`, `pending` or `failed`;
  - uploads its result as an artifact.

  A pending meeting is not an error; the dispatcher retries it.
- **Job `publish`.** Runs with `if: ${{ !cancelled() }}`. It:
  - merges whichever artifacts exist, so one broken country never blocks the others;
  - regenerates `data/manifest.json`, `schedule.json` and `health.json`;
  - runs the full validation, the full build and the asset-count guard (< 20,000 files);
  - commits only when bytes changed;
  - pushes, rebasing and retrying up to three times on non-fast-forward.

  The push triggers Cloudflare Workers Builds.
- **Job `verify-live`** (5 minutes after publish): fetches the live `/api/v1/latest.json` and compares release hashes against the manifest. On mismatch it opens an issue.
- **Issues:** one issue per country and failure class. Updates edit the issue body rather than adding comments. The issue closes automatically on recovery.
- **Freshness metadata:** `health.json` stores `checkedAt` per country. It is committed only when a status changes or a check is older than 7 days. The UI shows "Last change 7 Oct 2026 · checked within 7 days".

### Workflow `validate.yml` (PRs and human pushes)
Runs schema validation over all releases, adapter fixture tests, typecheck, build and bundle budget.

*Flagged:* adapter fixture tests and a schema-validation test are added because an unattended pipeline is publishing financial data.

### Adapters
- Each adapter is a pure parser over a fetched response, with recorded fixtures.
- Requests send an identifying user-agent.
- Parsers fail closed on unexpected markup.
- No adapter writes; `run.ts` owns all writes.

## 5. Decision-day state (one state machine, everywhere)

`scheduled` → `in-session` (meetingStart ≤ now < announceAt) → `due` (now ≥ announceAt, not yet verified) → `verifying` (retry ladder running) → `verified`.

**Every surface uses it:**
- the page;
- `document.title`;
- `latest.json` (via `schedule.json`);
- MCP `get_policy_rate`;
- WebMCP.

**During `due` and `verifying`:**
- The hero shows the prior level as "5.25% until today's decision is confirmed".
- The chart shows a hatched pending step at the announcement date.
- The title avoids "today".

**On `verified`:** the decision moment plays (§6.4).

**Where the state is computed:** on the client, after mount, from `schedule.json`. Static HTML never claims a state that depends on the clock.

## 6. Experience

### 6.1 Information architecture
- **Country pages are the front door.** `/{cc}/` is where search traffic lands.
- **Routes:**
  - `/` The world now: pulse, latest decisions worldwide, sortable table.
  - `/{cc}/decisions/{date}/` Decision page.
  - `/methodology/` and `/developers/`.
- **Legacy URLs:** `_redirects` (static, free) maps `/countries`, `/country/us`, `/decision/:id` and `/limitations`. `/as-of` and `/?country=` are prerendered pages with a tiny inline redirect script, because `_redirects` cannot match query strings.
- **Vercel:** the old project is disconnected from Git and redeployed once as a redirect-only `vercel.json` with 301s to the new domain. That deployment is kept permanently.

### 6.2 Country page: the first 600 px on a phone (no controls in this space)
1. Instrument · authority.
2. The value. Range: "3.75 to 4.00%". Shown with its move: "▲ +25 bps from 5.25%".
3. The lede: one sentence generated from records, e.g. "The RBI raised the policy repo rate by 25 bps to 5.50% on 7 Oct 2026, its first hike since February 2023, after ten months unchanged at 5.25%." Series-dated countries say "effective".
4. The next decision, in the bank's time and the viewer's: "Fri 5 Dec, 10:00 IST · 05:30 your time".
5. Freshness: "Verified against RBI · last change 7 Oct 2026".
6. A 160 px step chart of the current and previous cycle.
7. One row: "Since you borrowed".

**Below the fold:**
- **Full timeline.** Ranges are named in the subject's own units: This cycle / Since 2008 / Since 2000.
- **Decision ledger.**
- **Cycles.**
- **"What the repo rate is".** A three-sentence explainer.
- **Transmission.** How this rate reaches loans in this country, and where it doesn't.
- **Sources and methodology.** Includes exports (CSV, JSON, PNG, SVG) and a citation.

### 6.3 Decision page (long-tail search)
- **Header:** announcement date and time, level, change, and vote (or "Vote not captured").
- **The statement:** a quoted excerpt plus a link to the statement.
- **Context:** effective date; the decisions before and after.
- **"Same week elsewhere":** other banks that decided that week.
- **Citation and sharing:** a citation and the decision stamp as an OG image.

### 6.4 Signature concepts (specimen v4 is the reference)

Every country page answers the questions in the same order, so the IA is the product:

1. **The decision (hero).**
   - A card tinted in the direction of the move, with the value, the move pill ("+25 bps from 5.25%") and the lede.
   - Facts: decided or effective date, stance (when published), verification, next decision, record start.
   - Beside it, four insight tiles, each linking to its section: "How high is it", "Where in the cycle", "Against the Fed", "Among N central banks".
2. **Your loan.**
   - Amount, years and rate in local currency and number format: ₹ with lakh grouping, £, €, R$ and so on.
   - Two modes: "This decision" and "Since I borrowed".
   - Results: the payment change, the tenure alternative and interest over the loan.
   - The country's transmission note sits beside it.
3. **The cycle.**
   - Every earlier cycle in the same direction, overlaid from its first move, with a median line.
   - The current cycle in the move colour.
   - A list of every cycle in the record, synced to the chart on hover.
4. **Against the Fed (against the ECB for the US).**
   - The gap over time with a zero line.
   - The finding states the share-of-days rank. A "narrowest since" clause appears only when it reaches back more than a year.
5. **The record.**
   - The step chart with eras shaded (India's pre-Oct 2004 auction era, per D3).
   - The decision-day preview and Replay.
   - A recent-decisions ledger synced to the chart.
6. **The world now.**
   - The hikes and cuts pulse: diverging bars per quarter across all banks.
   - Latest decisions worldwide.
   - A sortable table (rate, last move, past-12-months change, state, gap to the Fed) that reorders with FLIP animation.

The policy stripes and the rates-by-year heat matrix are **dropped**. The owner found them unclear, and the pulse plus the table answer the same questions directly.

**Recommended addition (Phase 3b): real policy rate.** The policy rate minus headline inflation, from official CPI (MoSPI, BLS, Eurostat HICP, ONS, StatCan, ABS, IBGE). It answers whether policy is actually tight, the single most-asked analyst question. It has the same pipeline shape and stays $0.

### 6.5 Motion language: "the interface eases; the data steps" (specimen v4 is the reference)

- Composited properties only.
- One rAF loop at a time.

### 6.6 Visual system: the home.ashwingopalsamy.in language

**Shell.**
- A dark frame (`#1c1b1a` light, `#070708` dark) holds a 64 px icon rail and one rounded canvas (20 px radius).
- The toolbar is sticky, with a rolling crumb and meta, a country chip (code disc, name, value) and search (⌘K).
- On phones the rail becomes a bottom bar.

**Page anatomy.**
- **Heading and lede:** an h1 (authority · instrument), then the lede as the 16 px summary with mono numerals, then a "Verified against RBI" chip.
- **Stat strip:** six tiles separated by hairlines, each with a label, a 22 px mono value, a spark and a footnote:
  - current rate (5-year step spark);
  - last decision (last 16 moves as signed bars);
  - moves since 2000 (per-year bars);
  - range since 2000 (gauge with the current marker);
  - longest hold (hold-length bars);
  - rank among peers (bars, with this country in the accent).
- **Rows:** 12-column rows split by hairlines.

**Colour.** The owner's Claret palette by default (Clay switchable from the rail). Colours are hex values from Agam's `tokens.css` and `palettes.css`, light and dark tuned separately. One job per colour:

**Colour vision.** Hike and cut never rely on colour alone. They also differ in glyph (▲ vs ▽), sign (+/−) and direction (up vs down bars), and every chart has values in its tooltip. Clay maps hawk and dove to orange and blue, the safest pair for colour-vision deficiency.

**Type.** Owner rule, 7 Oct 2026:
- A number inside a sentence (lede, findings, notes, labels) is set in Inter with tabular figures, never Geist Mono.
- Geist Mono is reserved for numbers standing alone (table cells, stat values, chips that hold only a number), chart axes and ticks, diagrams and hashes.
- In prose, money uses the full locale format ("R$ 300.000", "₹50,00,000"), never compact abbreviations like "R$ 300 mil".
- Uppercase only on short context labels.
- Small text ≥ 4.5:1 contrast; non-text marks ≥ 3:1.

**Surfaces and cards.** Owner rules, 7 Oct 2026:
- **One `Card` component for every section.**
  - The same 16 px radius, 1 px hairline, 20/24 px padding and header anatomy: kick (question), finding, optional actions, body, optional footer.
  - Cards in a row stretch to equal height, and their content is laid out so no card shows a dead area. A shorter neighbour gets real content (for example the record facts), never blank space.
- **No full-card direction tints.** Hawk and dove colour lives only on small marks: glyph, pill, line, bar.
- **Surfaces stay neutral** in both themes.
- **Shadows** only on popovers, the palette, tooltips and the decision stamp.
- **Footer and page furniture** align to the same grid as the cards.
- **Zero tolerance**, enforced by automated layout guards at 360, 768, 1280 and 1440 px in both themes (Plan 2):
  - overlaps;
  - clipped or ellipsised values;
  - range values wrapping;
  - misaligned table columns;
  - controls whose text collides with neighbours.

**Not allowed:**
- Gradients, glows and glass.
- Colours invented outside the owner's palettes.
- En and em dashes in the UI.

### 6.7 Accessibility and mobile
- **No drag required (SC 2.5.7).** Every drag has a non-drag alternative: date fields ("On date", "Since"), tap-to-place, keyboard stepping (arrows, Home/End).
- **Countdown.** The absolute time comes first; the relative time is coarse and updates each minute and on `visibilitychange`. `role="timer"` with `aria-live="off"`; only state changes are announced (polite).
- **Charts:**
  - Each has a table alternative and a live readout.
  - Markers are keyboard reachable.
  - The SVG carries a summary `aria-label`.
- **Mobile:**
  - `touch-action: pan-y` on charts: horizontal drags scrub, taps place.
  - The country switcher is a bottom sheet in thumb reach, closed by Back.
  - Decision details open in a sheet that carries the decision page's URL.
  - Phones default to "This cycle".
  - Touch targets ≥ 44 px, and no information depends on hover.

### 6.8 Rendering, performance, SEO
- **Prerendering.** Every route is prerendered with React 19 `renderToString` and then hydrated. Prerendered HTML contains absolute dates only. Countdowns, relative times and decision-day state appear after mount.
- **Dates.** Dates are plain dates formatted in UTC, so no time zone can shift them.
- **Release ids.** HTML embeds its release ids. The client fetches the immutable `/api/v1/releases/{cc}/{hash}.json` and `latest.json` (revalidated) to detect anything newer.
- **Bundle.**
  - Plain CSS tokens, `lucide-react` icons, and hand-built SVG charts on a small local scale module (no d3).
  - Data loads per country.
  - Budgets enforced in CI.
- **SEO.** Each page gets a title, meta description and canonical URL; country pages carry `Dataset` JSON-LD with `<` escaped. The build generates `sitemap.xml` and `robots.txt`.
- **Titles.** Titles state the dated fact ("RBI repo rate: 5.50%, raised 7 Oct 2026") and never "today".
- **OG images.** Generated at build in Phase 4: the pulse for `/`, the hero card for country pages, and the decision stamp for decision pages.

## 7. Agent surface

- **REST** (static files, CORS `*`):
  - `/api/v1/countries.json`, `latest.json`, `schedule.json`;
  - `/api/v1/countries/{cc}.json`, `/api/v1/countries/{cc}/decisions.csv`, with CSV cells starting `= + - @` neutralised;
  - `/api/v1/releases/{cc}/{hash}.json`, which is immutable.

  Breaking changes go to `/api/v2/`, and `/api/v1` stays frozen.
- **Discovery:** `/openapi.json` (OpenAPI 3.1 generated from the schema), `/llms.txt`, Markdown twins (`/{cc}.md`), `/.well-known/mcp/server-card.json`.
- **MCP at `/mcp`** (stateless Streamable HTTP, `@modelcontextprotocol/server`, the same pattern as Agam).
  - **Data:** reads compact step indexes precomputed at build (a few KB per country) through `ASSETS`. It never parses full releases per request, which keeps it within the 10 ms CPU limit.
  - **Tools** (read-only):
    - `list_countries()`.
    - `get_policy_rate({ country, date, basis: 'effective' | 'announced' })`. Returns the level, or an explicit "no rate target" for that era, plus the decision and sources, plus the decision-day state when one applies.
    - `get_decisions({ country, from?, to?, direction?, limit ≤ 100 (default 20), cursor? })`.
    - `get_upcoming_decisions({ days ≤ 120 })`.
    - `compare_policy_rates({ countries ≤ 12, date })`.
  - **Validation:** dates must be real calendar dates within coverage.
  - **Output:** `structuredContent` plus a template-generated text mirror.
  - **Headers:** set in code, because `_headers` doesn't apply to Worker responses.
- **WebMCP:**
  - **API:** only `document.modelContext.registerTool(tool, { signal })` (the current API; `navigator.modelContext` is deprecated). Tools re-register on `pageshow` with `persisted`.
  - **Read tools** mirror MCP, served from in-page data, with `readOnlyHint` and `untrustedContentHint`.
  - **UI tools** (`open_country`, `set_range`, `pin_date`, `focus_decision`) are not read-only.
  - **Origin trial:** production needs a free origin-trial token.

## 8. Hosting and caching ($0)

- **Platform.** Cloudflare Workers free plan with static assets, on `rates.ashwingopalsamy.in`. That zone already serves the sibling site.
- **Worker routing.** `run_worker_first` covers only `/mcp`. Everything else is served as assets, which are free and unlimited, so the site keeps working even if the Worker quota is exhausted.
- **Rate limiting.** One free WAF rate-limiting rule on `/mcp` (per IP, 10 s period) runs before the Worker. A Worker-level limiter is the second line.
- **`_headers`.** Uses `! Cache-Control` to stop rules from merging:
  - HTML and mutable JSON get `max-age=0, must-revalidate` (ETag).
  - Release files and hashed assets get `max-age=31536000, immutable`.
- **Deploys.** Workers Builds on push to main (free: 3,000 minutes a month, one concurrent build).
- **Cron.** The Cron Trigger is free.
- **Analytics (optional).** Cloudflare Web Analytics: free and cookieless.

## 13. Risks

- **Scraped decision sources** (CN, ID, BI, JP statements) can break. Mitigation: fail closed, keep the last good release, the retry ladder, an issue, and fixtures.
- **RBA's firewall** may block GitHub runners. The fallback is the HTML cash-rate page; if that also fails, the country ships `planned`.
- **Historical calendars** are a research cost. `ledgerFrom` keeps partial ledgers honest.
- **Calendars need yearly updates.** A calendar-health issue fires when a country has fewer than two future meetings. CN is exempt because it is unscheduled.
- **WebMCP is pre-standard.** It is feature-detected and isolated in one module.
